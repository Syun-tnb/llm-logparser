# README Comparison: Codex (GPT-5.4) vs Claude Opus 4.6

このドキュメントは、同一の元README（日本語版）をもとに、
異なるLLMで「書き直し」を行った結果を比較した実験ログです。

単なる翻訳ではなく、「READMEとしての完成度」を評価対象としています。

---

## 🎯 実験の目的

* LLMごとのドキュメント生成能力の違いを観察する
* 「翻訳」と「再設計」の違いを明確にする
* OSS READMEにおける最適な構成パターンを探る

---

## 🧪 実験条件

* 入力: 既存の日本語README
* タスク: 「読みやすく・伝わるREADME」に書き直す
* モデル:

  * Codex（GPT-5.4系）
  * Claude Opus 4.6
* 制約:

  * 内容の意味は維持
  * 構成・表現は自由に変更可

---

## 📄 生成物

| モデル             | ファイル                                  |
| --------------- | ------------------------------------- |
| Codex (GPT-5.4) | `README_ja_rewrite_Codex_GPT5.4.md`   |
| Claude Opus 4.6 | `README_ja_rewrite_Claude_Opus4.6.md` |

---

## 🧠 比較観点

以下の観点で評価を行った:

* 読みやすさ
* 情報構造の明確さ
* ユーザー導線（どこから読めばいいか）
* ワクワク感 / 使いたくなるか
* リファレンスとしての実用性

---

## 🥊 比較結果（要約）

### Codex（GPT-5.4）

**特徴:**

* 情報整理が非常に強い
* 導線がシンプルで迷わない
* 実務ドキュメントとして優秀

**強み:**

* Quick Start が分かりやすい
* セクション構造が安定している
* 必要な情報にすぐ到達できる

**弱み:**

* やや無機質
* 「使いたくなる」演出は控えめ

---

### Claude Opus 4.6

**特徴:**

* ストーリー性と体験設計が強い
* 読み物として面白い
* プロダクトの魅力を引き出す

**強み:**

* キャッチコピーが強い
* 「できあがるもの」の見せ方が上手い
* OSSとしての世界観・作者性が出る

**弱み:**

* 若干冗長になりやすい
* リファレンスとしては少し探しづらい箇所がある

---

## ⚖️ 結論

この比較は「どちらが優れているか」ではなく、
**READMEに求める役割の違い**を示している。

| タイプ               | 向いているモデル    |
| ----------------- | ----------- |
| 使わせるREADME（体験重視）  | Claude Opus |
| 迷わせないREADME（実用重視） | Codex       |

---

## 💡 インサイト

今回の実験で最も重要だったのは、モデルの性能差ではなく:

> **プロンプトがタスクを定義する**

* 「翻訳しろ」 → 正確だが平坦な文章になる
* 「READMEとして書き直せ」 → 構造と体験が設計される

つまり、

> **翻訳と再設計はまったく別のタスク**

---

## 🧩 推奨アプローチ（ハイブリッド構成）

実運用では、両者の強みを組み合わせるのが最適:

1. 冒頭（キャッチコピー・導入） → Claude型
2. Quick Start → Codex型
3. 使用例・アウトプット → Claude型
4. コマンド・リファレンス → Codex型
5. アーキテクチャ・思想 → Claude型

---

## 📝 補足

この実験は、LLMを使ったドキュメント生成の一例であり、
最終的な品質はプロンプト設計に大きく依存する。
